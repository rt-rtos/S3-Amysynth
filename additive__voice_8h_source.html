9/* ── Additive / partials voice engine (AMY BYO_PARTIALS) ─────────────────────
10 * Wraps AMY's build-your-own partials wave type as one melodic voice: a
11 * BYO_PARTIALS control osc (osc 0) plus N PARTIAL sine oscs (osc 1..N), so
12 * oscs_per_voice is N+1. There is no algo_source[] routing: partials_note_on()
13 * derives the child set from the parent's `preset` (= N) and osc adjacency
14 * (child i at parent+1+i), and render_partials() drives each child's per-block
15 * amplitude from the parent's post-envelope amp via COEF_VEL. So the parent
16 * carries the shared amplitude envelope (the per-track ADSR editor targets
17 * osc 0, as with the FM control osc) and the children carry the spectrum.
18 *
19 * Pitch: AMY's logfreq is in octaves, so a partial at ratio r gets
20 * freq_coefs[COEF_CONST] = log2f(r) on top of COEF_NOTE tracking - inharmonic
21 * (bell) ratios are as expressible as harmonics.
22 *
23 * Per-partial `level` is that partial's amp_coefs[COEF_CONST]; 0 silences it,
24 * which is how presets use fewer than ADD_MAX_PARTIALS without changing the
25 * osc layout. Optional `decay_ms` adds a local decay-to-zero EG0 so upper
26 * partials ring down faster than the parent envelope (the bell preset relies
27 * on this); 0 follows the parent alone. */
28
29/* Hard ceiling on the partial count: a voice costs ADD_MAX_PARTIALS + 1 oscs
30 * from the global pool, so 13 oscs/voice worst case keeps a 4-row x 4-voice
31 * additive layer at 208 oscs, under budget. Compile-time fixed, like
32 * FM_NUM_OPS. */
33#define ADD_MAX_PARTIALS 12
34
35typedef struct {
36 uint8_t num_partials; /* 1..ADD_MAX_PARTIALS (N) */

38 float level[ADD_MAX_PARTIALS]; /* 0..1 relative level of each partial */
39 float decay_ms[ADD_MAX_PARTIALS]; /* per-partial decay; 0 = follow parent */
40} additive_voice_t;
