9/* ── Additive / partials voice engine (AMY BYO_PARTIALS) ─────────────────────
10 * Wraps AMY's build-your-own partials wave type as a single melodic "voice":
11 * one BYO_PARTIALS control osc (osc 0, relative) plus N PARTIAL sine oscs
12 * (osc 1..N, relative), so oscs_per_voice is N+1. Unlike the FM/ALGO voice
13 * there is no algo_source[] routing table: at note-on AMY's
14 * partials_note_on() derives the child set purely from the parent's `preset`
15 * field (= N) and osc adjacency (child i lives at parent+1+i), and
16 * render_partials() drives every child's per-block amplitude from the
17 * parent's post-envelope amp via the velocity -> amp_coefs[COEF_VEL] path.
18 * The parent therefore carries the voice's shared amplitude envelope (the
19 * row's per-track ADSR editor targets osc 0, exactly as it does the FM
20 * control osc); the children carry the spectrum.
21 *
22 * Pitch math: AMY's logfreq is in octaves, so a partial at frequency ratio r
23 * gets freq_coefs[COEF_CONST] = log2f(r) on top of COEF_NOTE tracking —
24 * harmonic 2 is +1.0 octave, harmonic 3 is +1.585, and inharmonic (bell)
25 * ratios are equally expressible.
26 *
27 * Per-partial `level` is that partial's own amp_coefs[COEF_CONST]; a level of
28 * 0 silences it, which is how presets use fewer than ADD_MAX_PARTIALS
29 * partials without changing the osc layout. Optional per-partial `decay_ms`
30 * adds a local decay-to-zero EG0 on that child so upper partials can ring
31 * down faster than the parent envelope (the bell preset relies on this);
32 * 0 means the partial follows the parent envelope alone. */
33
34/* Hard ceiling on the partial count: a voice costs ADD_MAX_PARTIALS + 1 oscs
35 * from the global pool (max_oscs = 250), so 13 oscs/voice worst case keeps a
36 * 4-row x 4-voice additive layer at 208 oscs — under budget with headroom.
37 * Fixed at compile time for the same reason FM_NUM_OPS is. */
38#define ADD_MAX_PARTIALS 12
