11/*
12 * render_clock — the master clock for the audio render loop.
13 *
14 * Emits exactly one "render now" signal per audio block period (256 samples
15 * @ 48 kHz = 5333.333 µs), independent of the FreeRTOS tick rate. Two backends
16 * implement this same header, selected at build time by
17 * CONFIG_RENDER_CLOCK_I2S_ENABLE (default OFF):
18 *
19 * - render_clock.c (default): a GPTimer whose alarm ISR is pinned to the
20 * render task's core and wakes it via a FreeRTOS task notification.
21 *
22 * - render_clock_i2s.c (opt-in, CONFIG_RENDER_CLOCK_I2S_ENABLE=y): an I2S TX
23 * channel with every GPIO left unassigned (no pin mux change, no physical
24 * signal). render_clock_wait() blocks on i2s_channel_write(...,
25 * portMAX_DELAY); DMA backpressure paces render, exactly like the
26 * shorepine/amy_dual_core_esp32 reference. Its DMA queue depth
27 * (CONFIG_RENDER_CLOCK_I2S_DMA_DESC_NUM) gives the render task look-ahead
28 * slack the GPTimer path does not have -- see docs/handoff/i2s-clock-source.md
29 * for the full design + impact trace. The render task body in main.c is
30 * unchanged either way; only this seam changes.
31 *
32 * STRICT 1:1: the caller renders exactly ONE block per render_clock_wait()
33 * return, never the backlog, so AMY's total_blocks stays locked to realtime and
34 * the sequencer tempo (derived from amy_sysclock()) cannot drift. This holds
35 * for both backends.
36 */
